# ±10 cm follow-up: larger detectors and multiple frames

Date: 2026-09-28. User target changed from ±5 cm to **±10 cm**; independently measured vehicle lengths and surveyed road distances are unavailable.

**Outcome: improved repeatability and safer saved measurements; absolute ±10 cm accuracy has not been demonstrated.** The existing eight unique reference annotations still have a maximum fitting error of **16.21 cm** (MAE 8.21 cm; 4/8 within ±10 cm). These are training residuals against unverified legacy lengths, not independent true-length errors. No catalogue guesses were used to retune calibration.

## Identical-frame model comparison

Ran YOLO26 N, M and L at 640 and 1280 on **300 original frames in six short clips across all three supplied videos**: **1,800 inference calls**. This is a deliberately selected comparison, not a census of the recordings. The clips include four moving passenger cars, a loaded truck and a stationary van near but outside the trigger line. Each variant used the same lens correction, calibration, confidence 0.35 and duplicate suppression. Weights came from the [official Ultralytics release](https://github.com/ultralytics/assets/releases/tag/v8.4.0); available sizes are described in the [official YOLO26 documentation](https://docs.ultralytics.com/models/yolo26/).

Raw ranges below use detections within ±30 original image pixels of the line. The temporal estimate additionally requires an actual detection within the original ±10 px trigger gate and adequate calibration coverage. Range and residual are **repeatability diagnostics**, not absolute measurement error.

| Example | N 640 range | M 640 range | L 640 range | M temporal max residual |
|---|---:|---:|---:|---:|
| Black SUV | 11.31 cm | 2.40 cm | 3.03 cm | 1.43 cm |
| Silver hatchback | 6.17 cm | 3.06 cm | 2.53 cm | 1.21 cm |
| White MPV | 8.04 cm | 6.46 cm | 9.20 cm | 1.71 cm |
| Small white SUV | 7.96 cm | 7.11 cm | 7.35 cm | 2.96 cm |


M 640 was selected for the supplied ST preset and newly created profiles. It improves the largest SUV instability (11.31 → 2.40 cm), has the smallest average temporal maximum residual across these four passenger examples, and is substantially faster than M/L 1280 here. L remains selectable. Old profiles without a detector field retain N; changing detector size in the editor clears stale detections, retains annotations, and asks the operator to check calibration. Catalogue/model identity is not inferred from the detector class.

Median inference times on this CPU-only machine: N 640 13 ms; M 640 57 ms; L 640 75 ms; M 1280 255 ms; L 1280 320 ms. These exclude decoding, persistence and OCR; production CUDA throughput was not measured. Production still requires NVIDIA CUDA.

## Failure cases retained

The loaded truck is **not solved** by using a larger detector. M 640 puts its at-line boxes outside the supported calibration depth; L 640 and L 1280 fail the temporal stability check (maximum residuals 17.3 and 22.0 cm). Cab mirrors, load, body boundaries and partly hidden wheels remain possible shared biases even when boxes are stable. The application now saves an at-line, uncalibrated vehicle as a review record with a side photo and **no numeric length**. It does not extrapolate scale to make the truck pass.

The stationary van stays outside the original trigger tolerance and produces no crossing estimate. Its stable off-line boxes are not counted as successful at-line measurements.

## Saved-capture implementation

- Side detector model (N/M/L), input size (640/1280), and accuracy target are stored in the calibration profile. The ST preset uses M 640 and 0.10 m. The calibration inspector reports this target dynamically; it does not label it validated.
- Recorded-video captures requesting temporal analysis re-decode the original video within ±0.45 s of the anchor. They apply the original correction and selected detector to at most 31 distinct frames. Production browser automatic captures use this path; individual/manual still-image work remains an approximate single-frame measurement.
- A local robust linear fit estimates length at the line from at least five associated, fully visible and calibrated frames. It requires actual line evidence and a bracketed line position (or all evidence already within the original gate). Maximum residual and interleaved-fit disagreement must each be ≤0.10 m. Bad residuals are retained for rejection, not silently discarded. Ambiguous overlapping vehicles fail review.
- IP-camera automatic capture waits 0.45 s for subsequent frames, retaining the original side/front anchor and timestamp. Side buffering now permits up to 30 frames/s with the existing 100-frame/48 MiB limits. Reconnects cannot combine evidence from separate camera epochs. Slow inference or insufficient buffered frames can lead to review; acceptance is not guaranteed by increasing buffer rate.
- Saved records include the original single-frame length/status, each used frame index/bbox/length, exclusions, residuals, chosen model, resolution and `accuracy_validated: false`. Unstable/unsupported captures have no assigned length and require operator review. Rejected crossings do not get automatic numeric tariffs.

## Real pipeline replay

Invoked the actual `station.capture` → original-video refinement → persistence path with M 640 and the live confidence threshold **0.30**, using the first detected at-line box in each moving example. It ran in an isolated database under `runs/accuracy_10cm/production_capture`, with an explicit offline CPU inference override. Existing station data and uploaded videos were not modified. Photos and evidence were persisted through the real application logic.

## Reproduction and evidence

`runs/accuracy_10cm/manifest.json` contains source-video, model and profile SHA-256 hashes; `all_model_comparison.json` contains all 300 × 6 observations; `comparison_summary.json` contains all 36 case/variant outcomes, including failures. `production_capture/summary.json` records the real capture results. Original footage remains unchanged. Large runtime evidence and downloaded weights are ignored by Git.

```bash
.venv/bin/python scripts/compare_vehicle_detectors.py \
  --profile config/st-calibration.json \
  --cases runs/accuracy_10cm/cases.json \
  --models n=models/workbench/yolo26n.pt \
           m=runs/accuracy_10cm/models/yolo26m.pt \
           l=runs/accuracy_10cm/models/yolo26l.pt \
  --output-dir runs/accuracy_10cm_repeat --device cpu

.venv/bin/python runs/accuracy_10cm/replay_capture.py
```

`audit_measurements.py --tolerance-m 0.10` evaluates supplied independent ground truth at the chosen target; without it, accuracy remains unvalidated. Rejected and missed labelled observations count against all-ground-truth acceptance. Verifying physical accuracy still requires independent lengths and scale references covering the actual vehicle depths/body types. Retuning to these unlabelled clips would not establish that accuracy.
