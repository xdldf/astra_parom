# Проверка нескольких кадров в рабочем режиме — 28.09.2026

Изменения включены в обычное сохранение проезда из видео и автоматическое измерение с IP-камер. Отдельный переключатель не требуется. Используется модель, выбранная в применённом профиле; модель и параметры объектива этим изменением не заменяются.

## Исправленные причины пропуска

1. Страница видеозаписей получала только последний результат детектора. Если между опросами сервер успевал обработать несколько кадров, промежуточный результат у линии терялся. Сервер теперь хранит до 128 результатов, а каждый браузер получает новые результаты по своему счётчику. При переполнении показывается предупреждение. Это очередь результатов, а не гарантия обнаружения на каждом кадре видео.
2. Если машина пересекла линию между обработанными кадрами, раньше повторно проверялся один расчётный кадр. Теперь сервер просматривает соседние исходные кадры, сопоставляя рамку с движением той же машины. Поиск ограничен 31 кадром около расчётного момента и двумя наблюдениями не дальше двух секунд друг от друга. Неоднозначное совпадение с соседним автомобилем отклоняется.
3. В IP-режиме поиск в сохранённых кадрах расширен с трёх ближайших до ограниченного окна максимум 31 кадр. Сохраняются проверки переподключения и свежести.
4. Для оценки длины сначала используется прежняя узкая полоса. Если в ней меньше пяти пригодных кадров, окно расширяется до 20% ширины рамки, максимум ±120 исходных пикселей. По-прежнему необходим реальный кадр в исходном допуске линии, минимум пять измерений одного объекта, подходящая область калибровки и проверка устойчивости. Ранее принятые оценки из узкого окна сохраняются.
5. В карточке проезда отображается количество проверенных и использованных для длины кадров.

## Проверка на предоставленных видео

Повторный расчёт по сохранённым результатам детекторов на тех же 20 выбранных проездах, 1000 исходных кадров:

| Модель | Устойчивые оценки раньше | После изменения окна |
|---|---:|---:|
| YOLO26 M | 6/20 | 15/20 |
| RT-DETR X | 9/20 | 19/20 |
| RF-DETR Large, экспериментальный скрипт | 7/20 | 15/20 |

Это число числовых оценок, не процент точности или обнаружения всех автомобилей. В выборке есть буксирующие машины: длина одной рамки не подтверждает полную длину состава. Расширение окна уменьшает отказы, но не устраняет систематическую ошибку калибровки. Прежнее расхождение около 26 см для вероятного Patrol осталось; ±10 см не подтверждены.

Все записи сохранили статус проверки оператором. Последняя строка показывает отличие рабочего захвата от таблицы повторного расчёта: рабочий поиск сохранил более раннюю рамку вне области калибровки; получение числовой оценки в другом кадре не разрешает обход этой проверки.

## Проверка кода и применение

216 Python-тестов и 39 тестов интерфейса прошли. Регрессии проверяют потерянный промежуточный кадр, независимые счётчики браузеров, ограничение очереди, поиск по настоящим кадрам через API, сохранение и повтор запроса без дублирования, соседний автомобиль, расширенное окно и IP-поиск дальше трёх кадров. Скорость на рабочем GPU и при живом потоке на объекте в этой проверке не измерялась.
