# Номер длинного автопоезда — 2026-09-29

Исправлена потеря раннего фото номера при задержке обработки бокового кадра. Раньше `FrontHistory.select` сравнивал время нужного фронтального кадра с временем **последнего** обработанного кадра камеры и требовал неотрицательную разницу. Если камера уже ушла вперёд, разница становилась отрицательной и история кабины отклонялась. При сохранении оставался снимок кузова/прицепа, на котором номер мог отсутствовать.

Теперь выбор использует историю наблюдений вокруг времени события и принадлежность непрерывному проезду. Уже завершённые проезды кратко сохраняются отдельно, поэтому прибытие следующего автомобиля не удаляет доказательства для ещё обрабатываемого события. Между наблюдениями разных машин номер не назначается по одному лишь сходству рамок.

Для медленных составов допустимый возраст читаемого кадра увеличен с 12 до 30 секунд относительно события; запас хранения на задержку обработки — ещё 5 секунд. Ограничения: до трёх проездов, пять читаемых JPEG на каждый, 16 МиБ суммарно, до 512 записей геометрии без JPEG. Переподключение/перемотка назад очищают историю. Потеря автомобиля, интервал более 1,5 с и другое прочитанное обозначение начинают отдельный проезд. Это эвристическое сопоставление: ручная проверка принадлежности снимков сохраняется.

Таблица и заголовок карточки теперь явно показывают результат OCR с подписью «Распознано · проверьте по фото», несколько вариантов, ошибку чтения, отсутствие читаемого номера либо отсутствие снимка. Для таблицы API передаёт число вариантов, сохраняя компактный ответ. Ранее таблица уже показывала первый OCR-вариант, но состояния `error` и `not_found` выглядели как «Не указан», а заголовок карточки показывал только подтверждённое поле. Номер, введённый оператором, имеет приоритет; выбор OCR-варианта по-прежнему выполняется кнопкой «Использовать номер». Ошибка живого OCR также видна над фронтальной камерой.
