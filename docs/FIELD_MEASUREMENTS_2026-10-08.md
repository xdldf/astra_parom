# Данные для проверки точности длины менее 10 см

Цель: полная длина каждого транспортного средства, включая прицеп, промежутки
между частями состава и выступающий груз, когда состав стоит прямо. ST и HiWatch
остаются на существующих местах. Каталожные размеры и стабильность оценки по
кадрам не заменяют физический замер.

## На площадке

1. Запишите режим обеих камер: разрешение, объектив, фокус, цифровой зум и положение.
   Не изменяйте их между калибровкой и проверкой. Смена любого параметра требует
   новой калибровки. Отдельно сохраните дату и идентификатор установки.
2. Снимите калибровочную доску с известным размером клетки в разных положениях,
   наклонах и участках изображения. Нужны минимум 10 разнообразных положений
   для подгонки и 3 других для проверки на каждой камере. Повторные соседние
   кадры неподвижной доски не являются разнообразными положениями.
3. Задайте общую систему координат обеих камер. Измерьте минимум 6 точек на дороге
   и 4 приподнятые точки с реальными X/Y/Z, распределённые по зоне измерения.
   Высоты приподнятых точек нужно измерить; нельзя переносить краску на ограждении
   на дорогу с теми же пиксельными координатами. Цель для погрешности съёмки — 1 см
   или лучше; запишите фактическую погрешность инструмента и установки каждой точки.
4. Измерьте ещё минимум 3 точки на дороге и 3 приподнятые точки для независимой
   проверки. Эти точки не участвуют в подгонке. Точки должны покрывать ближнюю,
   дальнюю, левую и правую части используемой зоны. Текущий бюджет проверки — 3 см,
   включая указанную погрешность геодезической съёмки; это ещё не точность автомобиля.
5. Проверьте плоскость дороги. Модель принимает контакты колёс на плоскости Z=0.
   Уклон можно включить в ориентацию общей системы координат, но перепады и изгибы
   поверхности нельзя скрывать обнулением высот. Зафиксируйте их для отдельной модели.
6. Провезите физически измеренные автомобили разных типов, включая длинные составы,
   по разным положениям в полосе. Снимите начало и конец каждого проезда обеими
   камерами. Сопоставьте время по движению: дата на изображении HiWatch недостоверна.

## Таблица реальных длин

Для каждого физического автомобиля задайте постоянный ID; повторные проезды
получают тот же ID. Полную длину измеряйте между вертикальными проекциями крайних
точек на опорную плоскость, при прямом положении состава. Запишите метод, дату,
оператора и погрешность, включая выбор крайних точек. Не подставляйте оценку камеры.

Перед первым сохранением в `/evaluation` выберите «Калибровка» или «Независимая
проверка». Все проезды одного автомобиля должны относиться к одной выборке.
Назначение закрепляется: ранее использованный эталон нельзя превратить в независимый
проверочный пример. Для проверки необходимы физический замер, погрешность и ID.
Пропуск сохраняет возможность вернуться к записи; снимки сохраняются исправленными.

CSV для офлайн-оценки использует заголовок:

```csv
track_id,vehicle_id,length_m,uncertainty_m,reference_source,dataset_role
```

`track_id` связывает замер с конкретным проездом; `vehicle_id` связывает повторные
проезды физического автомобиля. Для независимых замеров укажите
`reference_source=physical_measurement` и `dataset_role=validation`.
Отсутствующие значения не означают нулевую погрешность. В результатах реконструкции
`complete_vehicle=true` допускается только после проверки, что крайние точки относятся
ко всему автомобилю/составу. Пропущенные проезды внесите в контрольную таблицу тоже.
Кнопка «Замеры проверки CSV» в `/evaluation` экспортирует независимые замеры;
исходные оценки камеры в колонку реальной длины не попадают.

Условие прохождения: `abs(оценка - физический замер) + погрешность замера < 0.10 м`.
Пропуски, отказы, неполные составы и несопоставленные обнаружения не проходят проверку.
Положительный результат на выборке не доказывает точность для всех будущих автомобилей.

## Формат геометрической калибровки

Существующая команда `calibrate.py survey` принимает `schema_version: 2`:

- `image_size`: действительное разрешение камеры;
- `units: "m"`, `coordinate_space: "raw_distorted_pixels"`;
- `world_frame_id`: общий ID метрической системы координат обеих камер;
- `road_polygon`: граница измеренной зоны в метрах;
- `control_points`, `check_points`, `raised_control_points`, `raised_check_points`;
- каждая точка: `id`, `xyz_m`, `uv`, `uncertainty_m`.

`uv` — внутренние координаты до коррекции объектива, соответствующие K/D. Нельзя
подставлять координаты с исправленного изображения напрямую. Отображаемые и сохранённые
снимки проверки остаются исправленными; исходное видео нужно для декодирования и калибровки.

```bash
.venv/bin/python calibrate.py survey --intrinsics runs/field/ST-intrinsics.json \
  --survey runs/field/ST-survey.json --calibration-id ST-field-2026 \
  --max-check-error-m 0.03 --output runs/field/ST-camera.json
```

Повторите для HiWatch. Эти файлы пока предназначены для диагностического решателя,
а не для импорта вместо рабочего профиля станции.

## Реконструкция по двум камерам

`scripts/reconstruct_camera_pair.py` читает rig JSON с `schema_version: 1`,
`coordinate_space: "raw_distorted_pixels"`, `rig_id`, `world_frame_id`,
`pose_camera: "ST"` и словарём `cameras`. Для каждой камеры укажите полный
`calibration` из предыдущей команды, `time_offset_s`, `time_uncertainty_s` и
`synchronization_verified: true` только после проверки синхронизации.
Общее время равно времени кадра плюс `time_offset_s`.

JSON наблюдений содержит те же `schema_version`, `coordinate_space`, `rig_id`
и `tracks`. Каждый трек содержит `track_id`, `complete_vehicle`, `pose_observations`
и `endpoints`. Поза: `timestamp_s`, `visible`, `rear_contact_uv`, `front_contact_uv`
на ST, необязательное `sigma_px` (по умолчанию 1 пиксель). Это стандартное отклонение
ошибки каждой координаты контактов, а не погрешность длины. Крайняя точка:
`camera_id`, `timestamp_s`, `landmark_id` (`front_extreme`
или `rear_extreme`), `uv`, `sigma_px`, `visible`. Следите за одной и той же физической
точкой: меняющийся край силуэта не является постоянной точкой кузова.

Решатель совместно подбирает постоянную колёсную базу, крайние точки кузова и
положение автомобиля в каждом кадре по ошибкам проекции в пикселях. Камеры остаются
фиксированными. Разброс колёсной базы, вычисленной отдельно для каждого кадра,
сохраняется в диагностике, но сам по себе больше не отбрасывает весь проезд.
Большая ошибка проекции или отдельный грубый промах контакта по-прежнему дают отказ.

Кадры со скрытыми контактами помечайте `visible: false`; их координаты можно
оставить `null`. Наблюдения крайних точек вне временного диапазона видимых контактов
или внутри разрыва более 0,25 с пропускаются и учитываются в диагностике. Другие
наблюдения проезда сохраняются. Экстраполяции нет; для каждого края нужны минимум
четыре поддержанных наблюдения и достаточная геометрия лучей. Совместная подгонка
снижает влияние случайных ошибок разметки, но не устраняет общий сдвиг точек,
ошибку калибровки или неверно выбранный физический край.

```bash
.venv/bin/python scripts/reconstruct_camera_pair.py --rig runs/field/rig.json \
  --observations runs/field/landmarks.json --output-dir runs/field/reconstruction \
  --ground-truth runs/field/validation-lengths.csv
```

Для состава вместо полей одной части задайте `components`: список с `component_id`,
`pose_observations`, `endpoints` для каждой части. `composition_verified: true` означает,
что разметчик проверил принадлежность всех частей одному проезду и полноту состава.
Решатель ищет общий интервал прямого положения (разница направлений до 1°), учитывает
промежутки и не складывает перекрывающиеся участки тягача и полуприцепа дважды.
Недостающая часть или отсутствие общего прямого интервала приводит к отказу.

Это условная реконструкция по заданным точкам. Автоматическое выделение точек и
принадлежности частей, а также проверенная точность на реальных автомобилях ещё
не готовы. Производственная оценка не переключается на этот решатель автоматически.
