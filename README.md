# Станция учёта автомобилей на пароме

Две камеры: измерение длины сбоку и чтение номера спереди. Режимы **IP-камеры** и **видеозаписи**, автоматические снимки, тарифы, проверка оператором, клиентский экран и журнал проездов.

## Быстрый запуск на другом компьютере

Нужны **Windows 10/11 x64, Python 3.11 x64, видеокарта NVIDIA с актуальным драйвером и Git**. Установка требует интернета и нескольких гигабайт свободного места для окружения и моделей. Работа без NVIDIA не поддерживается. На этой установке проверена RTX 4070 SUPER; скорость на другой видеокарте нужно проверить.

```powershell
git clone https://github.com/xdldf/astra_parom.git
cd astra_parom
.\INSTALL.cmd
.\START.cmd
```

Можно просто дважды щёлкнуть **INSTALL.cmd** в папке проекта, дождаться завершения, затем открыть **START.cmd**.

- **INSTALL.cmd** создаёт окружение, устанавливает проверенные версии библиотек, копирует комплектные модели и проверяет видеокарту. Обычно нужен один раз; при обновлении зависимостей запустите снова после остановки программы.
- **START.cmd** запускает сервер и открывает браузер. Оставьте окно запуска открытым. Для остановки — `Ctrl+C`.
- На сервере откройте <http://127.0.0.1:8000/>. Сервер слушает `0.0.0.0:8000`; другие операторы открывают `http://<IP сервера в локальной сети>:8000/`. `0.0.0.0` — адрес привязки, а не адрес для браузера.
- Права администратора обычно не нужны. Если установка завершилась ошибкой, прочитайте сообщение в окне; **START.cmd** не заменяет установку.

**Уточнение длины на ST-видео:** профиль `config/st-wheel-recovery-calibration.json` использует контур, колёса и резерв для разных положений машины. Установка моделей описана в [инструкции](docs/WHEEL_CAPTURE_2026-10-08.md), новые результаты и оставшиеся ошибки — в [проверке резервного расчёта](docs/WHEEL_RECOVERY_2026-10-08.md). Требование менее 10 см для каждой машины пока не достигнуто.

## Первое подключение

**IP-камеры:** выберите источник «IP-камеры» → «Настройка камер» → введите два адреса видеопотоков → сохраните → загрузите калибровку → «Подключить камеры». Адреса и пароли не приходят из GitHub: их нужно ввести на новом компьютере.

**Видео:** выберите источник «Видеозаписи» → загрузите боковое и фронтальное видео → загрузите калибровку → задайте сдвиг → «Пуск». Для наших исходных ST/HiWatch записей сдвиг +3 с; для другой пары его нужно проверить.

В комплекте `config/st-calibration.json` — текущая калибровка установки ST (2592×1944). Установщик копирует её только если своей настройки ещё нет. Она подходит только при сохранении того же изображения, положения камеры и параметров объектива. Для другой установки выполните калибровку заново.

Рекомендуемый вариант по устойчивости на предоставленных ST-видео — [`config/st-calibration-rtdetr-x.json`](config/st-calibration-rtdetr-x.json), **RT-DETR X / 640 px**. Нажмите «Загрузить настройку» и выберите этот JSON. Работающие камеры переподключатся автоматически; остановленные можно подключить кнопкой «Подключить камеры». Над изображениями оператор видит модель и разрешение из работающего серверного потока. Подробности и пределы проверки: [профиль и режим приблизительных оценок](docs/ST_RECOMMENDED_PROFILE_2026-09-29.md).

По запросу оператора рабочий режим теперь сохраняет приблизительную длину при пересечении рамки с дорогой: сначала используется низ рамки, затем другое пересечение. Выход за область эталонов и неустойчивые кадры помечаются «≈ Приблизительно», сохраняя причины и проверку нескольких кадров. Такие числа требуют проверки человеком; они не подтверждают ±10 см. В JSON это `measurement_mode: "estimate"` (также значение по умолчанию для старых JSON без поля). `"strict"` сохраняет прежние отказы без длины. Отсутствие масштаба, обрезанный автомобиль или неработоспособная геометрия не заменяются выдуманной полной длиной.

**Смена детектора:** на экране оператора раскройте «Изменить детектор», выберите модель и размер входа, нажмите «Применить модель». Открывать кадр или заново размечать дорогу не нужно. При смене работающей модели сначала проверяются новые веса; ошибка загрузки сохраняет прежний поток. IP-камеры автоматически переподключаются после применения. Синяя строка над камерами показывает настройку серверного потока.

**Калибровка по камере:** сохраните адрес боковой камеры → откройте «Калибровка» → «Кадр с камеры». Сохранённый профиль выбранного источника загружается автоматически. Инструменты разделены на детектор, зону дороги, масштаб и эталоны, место измерения и коррекцию объектива. «Отменить правку» восстанавливает предыдущую разметку; увеличение кадра не меняет координаты. Импорт/экспорт находится в «JSON и новая калибровка». Общая кнопка «Сохранить и применить» сохраняет профиль и переподключает работающие IP-камеры. Подробности — в [инструкции](README_RU.md#4-настройка-измерения).

Камеры независимы: без фронтальной камеры длина сохраняется без номера; без боковой продолжается чтение номера, но длина не выдумывается. Связь восстанавливается автоматически. В режиме IP сервер продолжает обработку после закрытия браузера.

## Что переносится через Git

Исходный код, установщик, тесты, инструкции, калибровка ST и базовые модели: YOLO26n, детектор номерных знаков и модель чтения номера. Веса и конфигурация лежат в [models](models/README.md) (около 21 МБ), приходят обычным `git clone`, Git LFS не нужен. Установщик проверяет SHA-256 и копирует отсутствующие файлы в рабочую папку. Базовые модели скачивать отдельно не требуется. Калибровка ST теперь использует YOLO26 M; M/L загружаются с официального сервера Ultralytics при подготовке выбранной модели или первом обнаружении (около 42/51 МиБ). В редакторе доступны YOLO26 N/M/L, RT-DETR L/X и 640/1280 px. RT-DETR использует официальный загрузчик Ultralytics; проверен вариант X при 640 px. Старые профили без поля detector_model сохраняют N.

**Видео, фотографии проездов, база и пароли камер в Git не входят.** Адреса камер вводятся локально, видео выбираются вручную.

Для переноса истории сначала остановите старый сервер и отдельно скопируйте `web_app/data` на новый компьютер. Эта папка может содержать персональные данные и пароли камер — не загружайте её в GitHub. После копирования переустановите зависимости через `INSTALL.cmd`; существующую калибровку установщик не заменит.

**Эталоны из истории:** после подтверждения автомобиля человеком отдельно введите его фактическую длину в разделе «Эталон для калибровки» и подтвердите проверку. Совместимые проверенные автомобили автоматически включаются в загружаемый и скачиваемый JSON. Неподтверждённые машины и обычные оценки камеры не добавляются. Подробнее — в [инструкции](README_RU.md#эталоны-из-списка-автомобилей).

## Полные кадры и проверка длины

Откройте **Проверка длины** в верхнем меню: полный кадр автомобиля → измеренная длина → поле фактической длины → **Сохранить и далее** или **Пропустить**. Пропущенные кадры можно открыть позже. Фактические длины сохраняются в JSON в `web_app/data/station/calibrations/` и доступны по кнопке **Скачать калибровку JSON**. Для применения новых эталонов загрузите JSON в калибровку и нажмите **Сохранить и применить**.

Если центр рамки не попал на линию из-за задержки обработки, программа сохраняет ближайший реальный кадр для проверки. Приблизительная длина отмечается; в строгом режиме такой кадр сохраняется без длины. Новые проезды сохраняют только полный исправленный кадр. [Подробности и ограничения](docs/CAPTURE_REVIEW_2026-10-08.md).

## Инструкции и ограничения

- [Исправление пустой длины с IP-камер](docs/IP_CAPTURE_RECOVERY_2026-09-29.md): кадры проезда удерживаются до окончания расчёта; причина отказа видна в очереди и карточке.
- [Проверка нескольких кадров в рабочем режиме](docs/CROSSING_RECOVERY_2026-09-28.md): поиск соседних исходных кадров при пропуске линии, сохранение промежуточных результатов между обновлениями страницы и расширение окна для быстрых проездов. Применяется автоматически при сохранении измерения; в карточке видно число использованных кадров.
- [Проверка дополнительных видео от 07.09.2026](docs/ADDITIONAL_VIDEOS_2026-09-28.md): 20 проездов, 1000 исходных кадров, YOLO M / RT-DETR X / RF-DETR Large. Есть сравнение с заводскими размерами и повтор через сохранение проезда. Цель ±10 см не достигнута; отдельно выявлено измерение прицепа без тягача.
- [Коррекция по метровым отметкам и ширине дороги](docs/ROAD_MARK_CALIBRATION_2026-09-28.md): добавлена подгонка объектива и проективной геометрии. `config/st-road-survey-review.json` — профиль для проверки: высота отметок неизвестна, перенос на дорогу не прошёл контроль; числовые длины в нём заблокированы.
- [Полевые замеры и независимая проверка](docs/FIELD_MEASUREMENTS_2026-10-08.md): какие точки и длины измерить на площадке, разделение калибровки и проверки, диагностическая реконструкция по двум камерам.
- [Обновление для цели ±10 см](docs/ACCURACY_10CM_2026-09-28.md): сравнение N/M/L на 300 кадрах, M 640 в профиле ST, оценка по нескольким исходным кадрам при сохранении проезда. Неустойчивые и некалиброванные проезды у линии сохраняются для проверки без длины. Стабильность улучшена, но абсолютная точность ±10 см пока не подтверждена.
- [Первоначальная проверка точности на трёх видео от 04.09.2026](docs/ACCURACY_AUDIT_2026-09-28.md): целевая погрешность ±5 см пока не достигнута. Повторы эталонов больше не меняют вес калибровки; редактор показывает расхождение с эталонами. Вне диапазона глубин эталонов длина не выдаётся. Для независимой проверки добавлен `scripts/audit_measurements.py`.
- [Полная инструкция на русском](README_RU.md): запуск, камеры, измерение, номера, оператор, резервные копии и устранение ошибок.
- [Технические заметки](docs/TECHNICAL_NOTES.md).
- Согласование камер программное, по времени получения кадров; задержку нужно проверить на месте.
- Длина по изображению приблизительная, номер и категорию проверяет оператор. Касса и эквайринг не подключены.
- Несколько операторов работают через один серверный процесс. Камеры и GPU общие; запускайте один сервер, без дополнительных Uvicorn workers. Полноценной авторизации пока нет; используйте доверенную локальную сеть, не публикуйте порт в интернете.


## Параллельная работа и новые настройки

- Очередь и отчёты показывают до **250 автомобилей на странице**. Кнопки «Старее / Новее» открывают историю; фильтры ищут по всей базе, CSV выгружает все подходящие записи. Обновление неизменившегося списка не передаёт автомобили заново.
- **Экран клиента → Открыть отдельный экран** открывает общий список всех обнаруженных автомобилей, включая неподтверждённые: номер, боковое фото, длина, цена и метка **Подтвержден / Не подтвержден**. На мониторе 17″, 1280×1024 одновременно помещаются 20 автомобилей. Во вкладке «Экран клиента» можно выбрать 5, 10, 15 или 20 строк; настройка сохраняется для рабочего места и обновляет отдельное окно. В отдельном окне настройки и кнопки страниц скрыты, показаны последние автомобили. До подтверждения цена предварительная; новые автомобили появляются сверху. Ссылку с кодом **Место** можно открыть на другом компьютере, список общий для всех касс. Если запись изменена другим оператором, несохранённая форма сохраняется, а повторное сохранение старой версии отклоняется.
- Флажок **Показывать цены** скрывает суммы только на экране оператора и сохраняется в браузере. Расчёт тарифов, клиентский экран и отчёты не меняются. Общая настройка **Использовать тарифы** по-прежнему отдельно включает или отключает тарифы всей станции.
- IP-камеры обрабатываются сервером один раз для всех браузеров. Переход одного оператора к видеозаписям и закрытие вкладки не останавливают их. Кнопка остановки и настройка камер общие для всех.
- Раздел 6 тарифов соответствует приказу **№37/ПЯ от 08.09.2026**: 6.1–6.4 — 2700 / 5350 / 6450 / 8500 ₽; 6.5 — 9000 ₽; 6.6–6.8 — 9200 / 10950 / 14250 ₽. Для 6.6–6.8 выберите категорию «по грузоподъёмности» и введите тонны из документов. Сохранённые цены старых записей не пересчитываются.
- В калибровке добавлен **Масштаб и эталоны → Мерные отметки**: нажмите последовательно на реальные измеренные отметки вдоль полосы, например через каждый метр, затем **Готово**. Разные интервалы могут иметь разную ширину на изображении. Для нескольких полос нужны линии на ближней и дальней глубине. Уменьшение картинки в браузере не меняет координаты измерения. Подробности и ограничения — в [инструкции](README_RU.md#4-настройка-измерения).

## Обновление

Остановите сервер, сделайте резервную копию `web_app/data`, затем:

```powershell
git pull --ff-only
.\INSTALL.cmd
.\START.cmd
```

Если вы меняли исходники локально, сначала сохраните собственные изменения; не используйте принудительный сброс ради обновления.

### Длинные грузовики: фото номера и выбор категории

Фронтальная камера может выбрать читаемый кадр кабины за 30 секунд до измерения длинного состава. История разделена по непрерывным проездам: до пяти читаемых кадров на проезд, до трёх последних проездов, общий предел 16 МиБ. Для завершения уже начатой обработки предусмотрен запас хранения 5 секунд. Выбор привязан ко времени сохранённого события: более новый кадр фронтальной камеры или следующая машина не заменяют кадр нужного проезда. Разрыв наблюдения более 1,5 с, потеря машины или другой прочитанный номер разделяют проезды; переподключение и перемотка назад очищают историю. Неоднозначная граница между машинами не сопоставляется автоматически. Под фото указан сдвиг времени; кнопка «Кадр в момент измерения» открывает синхронный снимок. Сверьте автомобиль на обеих камерах. Если связать кадры не удалось, остаётся синхронное фото. Это работает для новых событий IP-камер и текущей сессии видеозаписей; утраченные кадры старых событий не восстанавливаются.

В таблице и карточке результат OCR помечен «Распознано · проверьте по фото». Если прочтение неоднозначно, показано «Несколько вариантов»; ошибка OCR и отсутствие читаемого номера показаны отдельно. Откройте запись, сверьте фото, нажмите «Использовать номер» и сохраните или подтвердите запись. Введённый оператором номер имеет приоритет.

YOLO называет тягач с полуприцепом общим классом «truck». Для длины свыше 11,90 м интерфейс предлагает уточнить категорию, а не сразу вводить цену вручную. Выбор «Тягач с прицепом / полуприцепом» позволяет рассчитать пункт 7; категория по грузоподъёмности требует данных документов. Программа не назначает тип состава по одной длине.

Для длинного состава масштаб по короткому эталонному автомобилю может быть непроверенным на краях изображения: выводится предупреждение. Сверьте полную длину с независимым измерением и используйте мерные отметки вдоль всей рабочей зоны. Числовая поправка без контрольной длины не применяется.


### Только измерение, без тарифов

Над списком автомобилей снимите флажок **«Использовать тарифы»**. Это общая настройка станции: она сохраняется после перезапуска и обновляется у других операторов. В этом режиме программа не рассчитывает тарифы; цены, денежные итоги и оплата скрыты, CSV не содержит столбцов тарифа. Измерение, фото, номера, категории и подтверждение для экрана клиента продолжают работать.

Само переключение не меняет цены и статусы ранее сохранённых записей. Новые или изменённые записи в режиме без тарифов сохраняются без цены. После включения тарифов такую запись нужно заново подтвердить с рассчитанной ценой перед отметкой оплаты. Если другой оператор изменил режим перед подтверждением, интерфейс попросит обновить запись.

Подробная проверка полигона дороги, положения bbox и альтернативной реконструкции по нескольким кадрам: [отчёт](docs/ROAD_POSITION_AND_MULTIVIEW_2026-09-28.md).
