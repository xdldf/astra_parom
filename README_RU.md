# Система измерения автомобилей и учёта проезда на пароме

## 1. Что уже работает

Программа работает с двумя IP-камерами или двумя синхронизированными видеозаписями, измеряет длину автомобиля у заданной линии, читает его номер с фронтальной камеры и предлагает тариф. Оператор проверяет данные, подтверждает запись и отмечает полученную оплату.

**Доступны два режима: «Видеозаписи» и «IP-камеры».** Переключатель находится над изображениями. Видеозаписи используются для тестирования, IP-камеры — для постоянной работы. Подключение описано в разделе 8.

В текущем проекте:

- Боковая камера ST — измерение длины.
- Фронтальная камера HiWatch — номер и фото автомобиля.
- На вашем компьютере обработка использует NVIDIA RTX 4070 SUPER. Переход на процессор при отказе видеокарты отключён.
- Данные, изображения и результаты хранятся на компьютере.
- Тарифы соответствуют переданной таблице. В неоднозначных промежутках требуется решение оператора.
- Оплата отмечается вручную. Подключения к кассе, эквайрингу и шлагбауму нет.

## 2. Обычный запуск на этом компьютере

1. Откройте PowerShell.
2. Выполните:

```powershell
cd C:\job\astra_paroms
.\.venv\Scripts\python.exe -m uvicorn web_app.main:app --host 0.0.0.0 --port 8000 --no-access-log
```

3. Дождитесь сообщения `Uvicorn running on http://0.0.0.0:8000`.
4. Откройте браузер по адресу <http://127.0.0.1:8000/>.
5. Окно PowerShell оставьте открытым: оно поддерживает работу программы.
6. Нажмите **Пуск** в интерфейсе.

Если программа уже открывается по этому адресу, запускать второй экземпляр не нужно. Сообщение о занятом порте обычно означает, что первый экземпляр ещё работает.

### Остановка и перезапуск

Нажмите **Пауза** в интерфейсе, затем `Ctrl+C` в окне PowerShell. Для повторного запуска выполните ту же команду. После обновления программы обновите страницу браузера. Записи и настройки при обычном перезапуске сохраняются.

### Установка на другом компьютере

Установите Git, Python 3.11 x64 и драйвер NVIDIA. Затем:

```powershell
git clone https://github.com/xdldf/astra_parom.git
cd astra_parom
.\INSTALL.cmd
.\START.cmd
```

`INSTALL.cmd` автоматически устанавливает окружение и модели, проверяет видеокарту и копирует комплектную калибровку ST, если настройки ещё нет. `START.cmd` открывает браузер после готовности сервера. Установщик не скачивает записи ваших камер и не переносит пароли или журнал: их нужно перенести отдельно, как описано в разделе 7.

Клонированный проект не обязан лежать в `C:\job\astra_paroms`: установщик и запуск определяют свою папку автоматически. Команды ручного запуска в этой инструкции используют путь текущего компьютера; на другом замените его своим.

Для установки библиотек нужен интернет и несколько гигабайт свободного места. Все используемые веса моделей уже включены в папку `models` и переносятся обычным `git clone`; установщик проверяет их целостность и копирует отсутствующие файлы в `web_app/data`. Существующие файлы моделей в рабочей папке сохраняются. Если установка сообщает о недоступной видеокарте, обновите драйвер NVIDIA и повторите проверку. Режим без NVIDIA отключён. После установки модели и обработка работают локально. Подробности — [главный README](README.md).

## 3. Запуск подготовленных видеозаписей

Пара записей уже сохранена в проекте. Исходные файлы были найдены здесь:

```text
C:\Users\alexe\Downloads\ST_2026-09-04_19-30-04.mp4
C:\Users\alexe\Downloads\HiWatch_2026-09-04_19-30-01.mp4
```

Если записи нужно выбрать заново:

1. **Открыть видео** — выберите боковую запись ST.
2. **Видео спереди** — выберите фронтальную запись HiWatch.
3. **Загрузить настройку** — выберите сохранённый файл калибровки `.json`, соответствующий боковой камере.
4. Для этой пары оставьте сдвиг фронтальной камеры **+3 секунды**.
5. Включите **Автоматическое измерение**.
6. Нажмите **Пуск**.

Сдвиг означает: на 120-й секунде ST берётся 123-я секунда HiWatch. Это компенсация начала именно этих файлов, а не универсальная настройка всех камер. Общая перемотка управляет обеими записями. Когда заканчивается общий доступный интервал, воспроизведение завершается.

Используйте один операторский сеанс воспроизведения. Повторное проигрывание того же участка или работа в нескольких окнах могут создать повторные записи.

## 4. Настройка измерения

Откройте **Калибровка**. Настройку выполняет ответственный за установку камер; оператору не нужно повторять её перед каждой сменой.

1. Откройте боковой кадр с хорошо видимой дорогой.
2. Ползунками исправьте искривление изображения. Ориентируйтесь на прямые неподвижные объекты, например ограждение.
3. Исправьте наклон влево или вправо.
4. Мышью обозначьте поверхность дороги минимум четырьмя точками.
5. Добавьте эталонные автомобили с известной действительной длиной либо мерные линии **Metric rulers** (см. ниже). Желательно использовать несколько положений по глубине дороги.
6. Установите вертикальную линию там, где автомобиль лучше всего виден сбоку. Измерение выполняется, когда центр рамки автомобиля достигает линии.
7. Проверьте результат на нескольких автомобилях с известной длиной.
8. Сохраните файл настройки и загрузите его в операторском окне.

Высота установки 6 м и расстояние 12 м сами по себе не заменяют калибровку. Длина оценивается по изображению, положению автомобиля на дороге и эталонам. Ограждение, перекрытие колёс, обрезанный кузов и сильный разворот автомобиля влияют на результат.

После перемещения камеры, изменения зума, разрешения, наклона или исправления искажений настройку необходимо проверить и при необходимости выполнить заново. Файл настройки должен соответствовать разрешению бокового изображения.

### Мерные линии: метр–метр–метр

Если масштаб отличается в центре и у краёв, используйте **Metric rulers · variable scale** после исправления объектива и разметки дороги:

1. Подготовьте физически измеренные отметки вдоль направления движения, на поверхности дороги. Например, равные интервалы по 1 м. Не расставляйте точки «на глаз» через равное расстояние на экране.
2. Укажите фактический шаг в **Distance between marks, m**, нажмите **Draw ruler**, последовательно щёлкните каждую отметку слева направо (или справа налево). Нужны минимум три точки. Завершите **Finish ruler**; ошибочную точку можно убрать **Undo mark**, незавершённую линию — **Cancel**.
3. Одна непрерывная линия задаёт масштаб только рядом с её глубиной: ±5% местной ширины дороги в изображении. Для нескольких глубин добавьте ближнюю и дальнюю линии; между ними масштаб интерполируется. Линии должны различаться минимум на 8% глубины дороги, а точки каждой — оставаться в пределах 10%. Для одной глубины используйте одну длинную линию.
4. Охватите линиями всю ширину автомобиля от заднего до переднего края. Длина складывается по отдельным интервалам, поэтому узкие центральные и широкие крайние метры учитываются отдельно. За пределами покрытия линий длина не выдаётся.
5. Сохраните JSON и загрузите его оператору. При наличии мерных линий они имеют приоритет над автомобильными эталонами. Старые JSON без линий продолжают работать по прежней модели.

Размер превью в браузере не влияет на координаты: точки сохраняются в исходном разрешении исправленного изображения. Фактическое изменение разрешения, обрезка или другое положение камеры требуют соответствующей калибровки. Исправляйте объектив и наклон до рисования линий.

Мерные линии улучшают учёт местного масштаба, но не устраняют ошибки рамки, высоты кузова, перекрытия и разворота машины. Сравните результаты с независимо измеренными автомобилями на разных глубинах и у разных краёв кадра. Точность по калибровочным отметкам сама по себе не доказывает точность измерения машин.

## 5. Работа оператора

1. Введите имя оператора и уникальный код **Место** (латинские буквы, цифры, дефис или подчёркивание). Дождитесь автомобиля в списке слева.
2. Выберите его. Появятся снимок сбоку, синхронный снимок спереди, длина, номер и тариф.
3. Нажмите на любое фото для увеличения. Закройте его кнопкой или клавишей `Esc`.
4. Проверьте, что на двух снимках один и тот же автомобиль.
5. В разделе **Номер автомобиля** проверьте номер по фото и нажмите **Использовать номер**. При необходимости исправьте символы в поле номера.
6. Проверьте категорию по СТС и длину, особенно для грузовиков, прицепов и составов.
7. При изменениях укажите причину. Нажмите **Сохранить** либо **Подтвердить**.
8. После фактического получения денег используйте **Отметить полученную оплату**. Эта кнопка только записывает факт оплаты в журнале; она не списывает деньги и не печатает фискальный чек.

Если запись ошибочная или повторная, используйте **Отклонить** с причиной. Оплаченные записи закрыты для изменения. Кнопка **Отменить изменения / обновить** убирает несохранённые правки формы.

Список показывает не более 250 автомобилей на странице и прокручивается внутри панели. «Старее / Новее» открывает другие страницы, «↻» возвращает к последним записям. Фильтры применяются ко всей истории. Новые проезды не сдвигают границу уже открытой старой страницы; изменения статуса по фильтру могут изменить её состав.

При параллельном редактировании одной машины сохраняется только актуальная версия. Чужое изменение не затирает вашу несохранённую форму: появляется сообщение, затем нужно загрузить актуальную запись кнопкой «Отменить изменения / обновить». Повторная отметка оплаты старой версии отклоняется. Разные автомобили можно обрабатывать одновременно.

Раздел 6 обновлён по приказу №37/ПЯ от 08.09.2026. Для грузовика с легковым/лодочным прицепом свыше 11,9 м выберите соответствующую категорию (9000 ₽). Для пунктов 6.6–6.8 выберите «Грузовой автомобиль по грузоподъёмности» и заполните тонны по документам: 15,001–24,00 т — 9200 ₽; 24,001–30,00 т — 10950 ₽; от 30,001 т — 14250 ₽. Это грузоподъёмность, не масса груза. Промежутки не заполняются автоматически; старые сохранённые тарифы остаются в истории.

### Номер автомобиля перед камерой

Система сначала определяет ближайший автомобиль в установленном фронтальном ракурсе, затем ищет номер в нижней части его изображения. Номера машин позади не используются как замена, если у ближайшей машины номер не виден. Обрезанный краем кадра номер не принимается.

Для сохранённого измерения проверяются несколько соседних кадров. Проверка перекрытия рамок помогает не перескочить на следующую машину. Это правило рассчитано на текущую фиксированную камеру и очередь автомобилей. При другом ракурсе, нескольких полосах, сильном перекрытии машин или ошибке обнаружения выбор может быть неверным — проверка снимков остаётся необходимой.

Похожие латинские буквы автоматически переводятся в кириллицу: `A→А, B→В, C→С, E→Е, H→Н, K→К, M→М, O→О, P→Р, T→Т, X→Х, Y→У`. Цифры сохраняются. Например, `C900HT14` отображается как `С900НТ14`. Это замена похожих символов, а не перевод слов. Сомнительные символы нельзя восстановить достоверно только по формату номера.

Для старой записи нажмите **Распознать снова**. Если подходящего фото нет либо номер закрыт, введите номер вручную. Результаты могут быть неполными при бликах, грязи, смазывании и маленьком размере номера.

## 6. Клиентский экран и отчёты

Кнопка **Экран клиента** показывает запись, подтверждённую на вашем рабочем месте. Нажмите **Открыть отдельный экран**: ссылка содержит код места, например `http://192.168.1.10:8000/?page=client&station=cashier-1`. Откройте эту же ссылку на клиентском мониторе. Для каждой кассы используйте свой код **Место**, чтобы подтверждения разных операторов не заменяли друг друга. Ссылка без `station` использует код, сохранённый в данном браузере, либо создаёт новый.

В разделе **Отчёты** задайте период и фильтры, затем выгрузите CSV. Таблица разбита на страницы по 250 записей; итоги и CSV охватывают все записи по фильтрам (на старых страницах — до выбранной границы списка для итогов). Проверьте, какие статусы включены в отчёт. Неподтверждённые предложения номера не равнозначны принятому оператором номеру.

Имя оператора записывается в историю изменений. Это подпись в журнале, а не система входа по паролю.

## 7. Где хранятся данные и как сделать резервную копию

Папка данных:

```text
C:\job\astra_paroms\web_app\data
```

Основные файлы:

- `station\station.sqlite3` — записи автомобилей и журнал изменений.
- `station\*.jpg` — фотографии автомобилей и номеров.
- `operator-calibration.json` — настройка измерения.
- `camera-pair.json` — выбранная пара записей и сдвиг.
- `ip-cameras.json` — адреса, параметры и отдельная настройка IP-камер.
- `workbench` — загруженные видео и модель измерения.
- `plate-models` — модели чтения номера.

Для простой полной копии остановите сервер через `Ctrl+C`, скопируйте всю папку `web_app\data` в резервное место и запустите сервер снова. Файлы с фотографиями нужны вместе с базой. Не удаляйте загруженные записи, пока хотите повторно читать номер по соседним кадрам. Следите за свободным местом: видео и фото занимают диск.

## 8. Подключение настоящих IP-камер

### Подготовьте адреса двух видеопотоков

Нужен адрес **видеопотока**, а не адрес веб-страницы камеры. Поддерживаются RTSP и потоки HTTP/HTTPS, которые декодирует установленный FFmpeg, в том числе MJPEG. Поддержка конкретного кодека и камеры проверяется подключением. Автоматического поиска камер и настройки через ONVIF нет.

Уточните у установщика или в документации каждой камеры:

- IP-адрес камеры или регистратора.
- Порт и путь основного видеопотока.
- Имя пользователя и пароль для просмотра.
- Разрешение и частоту кадров.

Общая форма адреса, **не готовый адрес вашей камеры**:

```text
rtsp://ИМЯ:ПАРОЛЬ@IP_КАМЕРЫ:554/ПУТЬ_ПОТОКА
```

Путь зависит от производителя и канала регистратора. Специальные символы в имени или пароле должны быть корректно закодированы для URL. Не присылайте и не публикуйте пароли. Компьютер должен иметь доступ к обеим камерам по локальной сети.

### Порядок подключения

1. Запустите программу командой из раздела 2.
2. Над изображениями выберите **Источник → IP-камеры**.
3. Раскройте **Настройка камер**.
4. Вставьте адрес бокового потока в **Боковая камера**.
5. Вставьте адрес фронтального потока в **Фронтальная камера**.
6. Для первого подключения задайте поправку задержки **0 секунд**, допустимую разницу **200 мс**.
7. Нажмите **Сохранить подключение**. Поля очистятся и покажут «Адрес сохранён». Пустое поле при повторном сохранении означает «оставить прежний адрес».
8. Загрузите файл настройки боковой камеры через **Загрузить настройку**. В режиме IP эта настройка сохраняется отдельно от видео. Если отдельной настройки ещё нет, используется существующая общая настройка — её нужно проверить для новой камеры.
9. Нажмите **Подключить камеры**.
10. Дождитесь двух изображений и сообщения **Камеры работают**. Для автоматического учёта должна быть включена галочка **Автоматическое измерение**.
11. Проведите контрольный проезд, выберите появившуюся запись и проверьте длину, номер и соответствие снимков.

Время перемотки и загрузка видеозаписей в режиме IP скрыты. Чтобы изменить адреса, сначала нажмите **Остановить камеры**, затем сохраните новые настройки и подключитесь заново.

### Если ещё нет настройки измерения

Сначала сохраните адреса. Кнопка **Скачать кадр для настройки** работает и до запуска измерений: она получает неподвижный снимок боковой камеры. Откройте этот снимок в разделе **Калибровка**, выполните настройку по разделу 4, сохраните файл и загрузите его, вернувшись в режим **IP-камеры**. Для полноценной настройки нужны кадры с автомобилями известной длины на разных участках дороги; один пустой снимок задаёт только геометрию.

Разрешение бокового потока должно совпадать с настройкой. При несовпадении программа приостанавливает измерения и сообщает об этом. После смены настройки снова нажмите **Подключить камеры**.

### Как работает согласование двух камер

Каждая камера читается отдельным непрерывным подключением. Программа хранит ограниченный буфер свежих кадров и подбирает пару по **времени получения на сервере**. Файловую поправку `+3 секунды` переносить на камеры автоматически нельзя.

Если фронтальное изображение одного события приходит позже бокового на 0,3 секунды, задайте поправку `+0,3`. Если раньше — `−0,3`. Диапазон поправки: от −2 до +2 секунд. Проверяйте её по одному и тому же автомобилю и событию в двух видах. Значение **Допустимая разница кадров** задаёт предел расхождения после поправки, от 40 до 1000 мс.

Важно: малое расхождение времени получения не доказывает одновременность экспозиции камер. Встроенные задержки, разные кодеки и нестабильная сеть могут менять фактическую разницу. Это программное согласование, а не аппаратная синхронизация. Для точной работы нужны стабильные потоки, проверенная поправка и контрольные проезды. По возможности настройте общий источник времени камер, но текущий приёмник не использует их NTP-метки напрямую.

Камеры работают независимо:

- Если пропала фронтальная камера, боковая продолжает показывать дорогу, измерять длину и сохранять автомобили. В записи будет боковое фото и пометка об отсутствии фронтального снимка; номер вводится вручную.
- Если пропала боковая камера, фронтальная продолжает показывать изображение и читать номер ближайшего автомобиля. Новые измерения длины не создаются, поскольку для них нет бокового изображения.
- Если обе камеры доступны, но согласованную пару подобрать не удалось, длина сохраняется без прикрепления несоответствующего фронтального фото. Фронтальная камера продолжает самостоятельное чтение номера.
- Отключившаяся камера переподключается автоматически. После восстановления снова сохраняются согласованные снимки. Номер следующей машины не подставляется задним числом в запись без фронтального снимка.

После обрыва боковой камеры возможно повторное обнаружение того же автомобиля — оператор проверяет дубли. Обрыв только фронтальной камеры не сбрасывает отслеживание автомобилей боковой камеры. Если связь есть, но длина не измеряется, проверьте разрешение и файл настройки.

### Работа без открытого браузера

В режиме IP обнаружение, измерение и сохранение выполняет сервер. Можно закрыть браузер: пока запущена программа в PowerShell, камеры продолжают работать. При повторном открытии страницы она подключится к уже работающему сеансу. Не запускайте несколько серверов или несколько процессов `uvicorn --workers`: текущая станция рассчитана на один процесс.

Галочка **Подключаться при запуске программы** включает подключение при следующем запуске сервера. Она не устанавливает службу Windows и не запускает программу при включении компьютера сама по себе. Для остановки используйте **Остановить камеры**. После полной остановки программы требуется снова запустить сервер.

Переключение **IP-камеры → Видеозаписи** останавливает сетевые камеры. Переключение обратно показывает сохранённую настройку, после чего можно нажать **Подключить камеры**. При включённой галочке подключения при запуске сервер после перезапуска снова включит IP-режим независимо от последнего выбранного режима страницы.

### Снимки и повторное чтение номера

При измерении сохраняются боковое фото, согласованный фронтальный снимок и до пяти соседних фронтальных снимков из буфера. Они остаются на диске после обрыва связи и остановки камер. Поэтому **Распознать снова** работает и без подключения к камере. Круглосуточная запись всего видео не ведётся — сохраняются события.

Буфер ограничен 100 сжатыми кадрами и примерно 48 МиБ на камеру; в него поступает не более 15 кадров в секунду. Пропуск старых кадров защищает от накопления задержки. Фактическая частота зависит от разрешения, сети и нагрузки компьютера.

### Хранение настроек и доступ

Адреса сохранены в `web_app\data\ip-cameras.json` на сервере. Ответы интерфейсу не содержат пароль и полный адрес; в браузерном хранилище они не сохраняются. **Сам файл содержит адреса, включая пароль, в открытом виде:** ограничьте доступ к папке Windows и защищайте резервные копии. Не отправляйте этот файл в общий чат.

Обычный запуск слушает `0.0.0.0:8000`. На сервере можно открыть `http://127.0.0.1:8000/`, на других компьютерах — `http://<локальный IP сервера>:8000/`. При необходимости разрешите входящий TCP-порт 8000 только из доверенной локальной сети в брандмауэре. `0.0.0.0` не вводится в браузер. Запускайте один серверный процесс: все операторы разделяют камеры, GPU и базу. В приложении пока нет полноценной авторизации; код места не является паролем. Не открывайте его в интернет и не настраивайте проброс порта роутера.

### Что проверено

На этом компьютере две исходные записи были переданы через локальный RTSP-сервер MediaMTX как два сетевых потока. Проверены приём обеих камер, автоматическое сохранение двух автомобилей, чтение номера, независимая работа исправной камеры при отключении второй и повторное подключение. Тестовые записи хранились отдельно от рабочего журнала. Подключение именно ваших физических камер ещё нужно проверить после ввода их адресов.

Приём использует таймауты открытия и чтения FFmpeg, описанные в [документации OpenCV](https://docs.opencv.org/4.10.0/d4/d15/group__videoio__flags__base.html). Для обычной работы с настоящими камерами устанавливать MediaMTX не требуется.

## 9. Если что-то не работает

| Проблема | Что проверить |
|---|---|
| Страница не открывается | Работает ли сервер в PowerShell, правильный ли адрес и порт. |
| Порт занят | Не запущен ли уже первый экземпляр программы. |
| IP-камера не подключается | Проверьте адрес именно видеопотока, пароль, доступность камеры с этого компьютера и выбранный канал регистратора. |
| Видео не идёт | Выбраны ли оба файла, нажата ли кнопка «Пуск», не закончился ли общий интервал. |
| Длина не появляется | Загружена ли правильная настройка, целиком ли автомобиль в кадре, находится ли он на дороге у линии измерения. |
| Номер не появился | Видна ли передняя машина и её номер; увеличьте фото, повторите чтение либо исправьте вручную. |
| Показывается другая машина | Проверьте синхронизацию двух видов, положение линии и фронтальный ракурс. Не подтверждайте неверную пару. |
| Программа недоступна для обработки | Проверьте видеокарту командой из раздела установки; посмотрите сообщение в PowerShell. |
| Видео тормозит | Оставьте один операторский сеанс, закройте лишние программы с нагрузкой на видеокарту; проверьте диск и исходный файл. |
| Изменения не сохраняются | Укажите причину; если запись обновилась в другом окне, обновите её. Оплаченная запись закрыта. |
| После обновления старые подписи | Обновите страницу браузера, при необходимости `Ctrl+F5`. |

Для диагностики сохраните текст ошибки сервера, время события, пример снимка и выбранный файл настройки. Не включайте в общедоступные материалы пароли камер.

IP-камеры общие для всех мест. Смена источника на «Видеозаписи», переход к отчётам и закрытие вкладки не останавливают серверное измерение. Явная кнопка «Остановить камеры», переключатель автоматического измерения и изменение калибровки действуют на всех операторов. Перед заменой калибровки остановите камеры общей кнопкой; загрузка файла сама их не останавливает.


### Длинные грузовики: фото номера и выбор категории

Фронтальная камера сохраняет до 5 читаемых кадров одного непрерывно отслеживаемого проезда за последние 12 секунд (не более 16 МиБ). Когда кабина уже проехала, а боковая камера измеряет весь состав, программа может выбрать более раннее фото номера. Под снимком указан сдвиг времени; кнопка «Кадр в момент измерения» открывает сохранённый синхронный снимок. Проверяйте, что на двух камерах один автомобиль. Разрыв наблюдения более 1,5 с, потеря машины, переподключение или другой прочитанный номер сбрасывают историю. Если связать кадры не удалось, остаётся прежний синхронный снимок. Это работает для новых проездов IP-камер и текущей сессии видеозаписей; утраченные кадры старых записей автоматически не восстанавливаются.

YOLO называет тягач с полуприцепом общим классом «truck». Для длины свыше 11,90 м интерфейс предлагает уточнить категорию, а не сразу вводить цену вручную. Выбор «Тягач с прицепом / полуприцепом» позволяет рассчитать пункт 7; категория по грузоподъёмности требует данных документов. Программа не назначает тип состава по одной длине.

Для длинного состава масштаб по короткому эталонному автомобилю может быть непроверенным на краях изображения: выводится предупреждение. Сверьте полную длину с независимым измерением и используйте мерные отметки вдоль всей рабочей зоны. Числовая поправка без контрольной длины не применяется.


### Только измерение, без тарифов

Над списком автомобилей снимите флажок **«Использовать тарифы»**. Это общая настройка станции: она сохраняется после перезапуска и обновляется у других операторов. В этом режиме программа не рассчитывает тарифы; цены, денежные итоги и оплата скрыты, CSV не содержит столбцов тарифа. Измерение, фото, номера, категории и подтверждение для экрана клиента продолжают работать.

Само переключение не меняет цены и статусы ранее сохранённых записей. Новые или изменённые записи в режиме без тарифов сохраняются без цены. После включения тарифов такую запись нужно заново подтвердить с рассчитанной ценой перед отметкой оплаты. Если другой оператор изменил режим перед подтверждением, интерфейс попросит обновить запись.
